## 문제
같은 박자로 움직이는 장애물들이 같은 클립을 요청하면 전역 0.05초 제한으로 가까운 장애물의 소리도 누락된다.

## 기대 결과
사용자가 0.05초 제한의 필요성을 재질문한 후 3D 단발음의 시간 제한을 제거하는 방향으로 단순화했다. 같은 위치·다른 위치 모두 같은 프레임에 각각 재생한다. UI의 중복 제한은 유지한다.

## 영향 범위 및 제약
- AudioManager의 3D 단발음 중복 제한. UI 기록은 분리하며 UI 자체 제한과 반복음 처리는 유지한다.
- 위치별 제한용 추가 필드와 기록은 최종 코드에서 제거했다. 기존 UI용 기록만 사용한다.
- 파일맵 Play에서 자연 발생 장애물 소리와 근처 재생 소스의 출력 신호를 확인한다. 검증 후 사용자의 후속 요청에 따라 펫 수정과 별도로 커밋한다.

## 열린 질문
- 없음. 사용자가 위치별 제한 수정과 Play 검증을 요청했다.

## 해결 기록
- Unity 컴파일 성공. 파일맵 Play에서 같은 프레임의 다른 위치·같은 위치 3D 요청 모두 성공, UI 첫 요청 성공·중복 차단, UI 직후 3D 요청 성공, 반복음 동시 요청 성공.
- 첫 검증에서는 가시 음원의 GUID `5cb925e37e628e34ea290f6dcf6d0296`가 Missing이었다. 이후 사용자가 원본을 추가해 정상 연결됨을 확인했다.
- Play 중에만 임시 생성 음원을 연결해 실제 가시 두 곳에서 약 2.8m 거리의 AudioListener로 각각 7초 관찰했다. 자연 재생 2회·3회, 소스 출력 peak 0.02719, 최종 출력 peak 0.03372·0.04090 확인. 원본 연결·카메라·BGM을 finally에서 복원했고 SO dirty false 확인.
- 원본 `ROBOTIC_Servo_Small_Short_Fast_Mechanical_mono.wav`로 파일맵 Play 재검증 성공. 같은 프레임 원본 클립의 먼 위치·가까운 위치·동일 위치 요청 모두 허용됐다.
- 실제 가시 두 곳에서 약 2.8m 거리의 청취 위치로 각각 7초 관찰했다. 원본 자연 재생 2회·3회, 실제 재생 voice 확인, 소스 peak 0.04947, 최종 출력 peak 0.27799·0.10442. 가시 원본 클립 최대 4개 동시 재생. 시험 음원 연결 없이 출력 신호로 검증했으며 직접 청취 평가는 하지 않았다.
- 검증 후 Play 종료, 원래 씬·백그라운드 설정·카메라·BGM 복원. 검증 단계에서는 커밋하지 않았고 이후 사용자 요청으로 별도 커밋한다.
