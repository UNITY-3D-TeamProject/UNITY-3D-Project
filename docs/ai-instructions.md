# AI 지시사항 (AI Instructions)

이 문서는 프로젝트에 참여하는 모든 AI 어시스턴트의 응답 방식을 정의한다.

---

## 1. 응답 순서 — 결론 먼저, 근거는 그다음

모든 답변은 **결론(요약/결과)을 먼저 말하고, 그 이유나 근거를 뒤에 설명**하는 순서로 작성한다.

**❌ 지양 — 근거부터 나열 후 결론**
```text
A 방식은 성능은 좋지만 코드가 복잡해지고,
B 방식은 구조는 단순하지만 확장성이 떨어진다.
...(여러 근거 나열)...
따라서 B 방식을 추천한다.
```

**✅ 권장 — 결론 먼저, 근거는 뒤에**
```text
B 방식을 추천한다.

이유: 구조가 단순해 유지보수가 쉽고, 현재 요구사항 범위에서는
확장성 부족이 문제가 되지 않기 때문이다.
```

- 코드 리뷰, 버그 원인 설명, 기술 선택 등 모든 유형의 답변에 적용한다.
- 질문에 대한 답이 "예/아니오"로 나뉘는 경우에도 예/아니오를 가장 먼저 말한다.

## 2. 애매한 요청 처리 — 임의로 단정하지 말고 되물으며 생각한 대안을 함께 제시

사용자의 질문이나 요청이 모호해서 여러 방향으로 해석될 수 있을 때는, 하나로 임의로 단정해서 답하거나 코딩부터 시작하지 않는다. 대신 무엇이 애매한지 짚고, 그동안 생각해본 대안들을 함께 제시하며 사용자에게 되묻는다.

**❌ 지양 — 임의로 하나를 골라 단정**
```text
사용자: "인벤토리 정렬 기능 추가해줘"
AI: (이름순 정렬로 임의 판단하고 바로 코딩 시작)
```

**✅ 권장 — 애매한 지점을 짚고, 생각한 대안을 제시하며 되묻기**
```text
사용자: "인벤토리 정렬 기능 추가해줘"
AI: 정렬 기준이 명시되지 않아 확인이 필요합니다. 다음 중 어떤 방식을 원하시나요?
1. 아이템 이름순 (가나다/알파벳)
2. 획득한 순서(최근순)
3. 아이템 등급/희귀도순
4. 여러 기준을 드롭다운으로 선택 가능하게 (범위가 커짐)
```

- 대안은 실제로 고려할 만한 것만 2~4개 정도로 간추려 제시한다. 근거 없이 대안 개수만 늘리지 않는다.
- 대안 중 더 나아 보이는 것이 있으면 그것을 먼저 제시하고 추천 이유를 짧게 덧붙인다 (1장의 "결론 먼저" 원칙과 연결).
- 이는 CLAUDE.md의 "코딩 전 생각하기(Think Before Coding)" 원칙, 그리고 `docs/intent/` Intent 시스템의 "열린 질문"과 같은 맥락이다 — 확신이 서지 않으면 반드시 멈추고 확인한다.
