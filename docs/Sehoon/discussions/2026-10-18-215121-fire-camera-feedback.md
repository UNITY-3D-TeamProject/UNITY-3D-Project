# 사격 카메라 피드백 조정 설계

- 목적: 가벼운 플랫포머 + TPS에서 과한 사격 셰이크를 완화할 후보와 검증 범위를 정한다.
- 참여: Codex(현황 확인·리뷰), Claude Code Opus(제공된 사실에 근거한 대안 비교). 구현 호출은 하지 않았다.

## 직접 확인한 현황

- Unity AssetDatabase로 확인한 `Player.prefab` 최종 Impulse는 Uniform/Bump, DefaultVelocity.y=-0.5, 지속시간 0.2초다. 원본 `LookPrefab`의 -1을 중첩 프리팹 override로 덮어쓴다.
- 차지샷 피치 반동 3도, 복귀 20도/초다. 일반샷 0.2배, 조준 중 추가 0.5배가 셰이크와 피치 반동에 공통 적용된다.
- 두 카메라 Impulse Listener Gain은 1이며 SecondaryNoise는 없다.
- 설치된 Cinemachine 소스에서 현재 타입은 ImpulseDuration을 사용하며 Legacy TimeEnvelope의 DecayTime은 사용하지 않는 것을 확인했다.

## 대안과 추천

| 안 | 셰이크 DefaultVelocity.y | 피치 반동 | 의도 |
|---|---|---|---|
| A | -0.5 → -0.25 | 3도 유지 | 사용자가 지적한 위치 흔들림부터 축소 |
| B | -0.5 → -0.25 | 3도 → 2도 | 조준 시점의 들림도 함께 완화 |

- Claude는 최소 변경인 A를 우선 추천했다. Codex도 셰이크 영향부터 비교하기 위한 1차 후보로 동의한다.
- 두 안 모두 기존 지속시간·복귀 속도·일반/차지/조준 배율을 유지하는 제안이다. 최적값이나 사용자 승인으로 확정하지 않았다.
- 변경 시 원본으로 Apply하지 않고 Player의 override를 대상으로 해야 한다. 씬별 override가 후보 값을 가리는지도 확인해야 한다.

## 사용자 확정 사항과 미결정 사항

- 사용자는 Claude와 협의·테스트하여 적절한 값을 적용하는 작업을 요청했다.
- 정책 수치와 단계별 구현 계획은 기존 협업 규칙에 따라 적용 전에 선택·승인이 필요하다. A/B 선택과 구현은 아직 미확정이다.
- 사용자는 표시기 미발견을 자동 시작 실패로 오판하여 수동 실행을 요구하지 않도록 전역 지침 갱신을 명시적으로 요청했다. Codex가 해당 전역 지침만 갱신했다.

## 검증과 다음 단계

- 현재 로비 씬은 저장 상태이며 Unity가 연결되어 있다. 컴파일 실패 플래그는 false였다. 플레이 테스트는 하지 않았다.
- 표시기가 화면에 실행 중인데 샌드박스의 probe는 미발견, 동일 명령을 샌드박스 밖에서 실행하면 성공하는 것을 확인했다. 현재 채팅 화면 대조 후 Claude 응답을 정상 수신했다.
- 승인 후 선택된 값만 Claude Sonnet에 구현 요청하고 Codex가 변경 범위를 리뷰한다.
- 일반/차지 × 비조준/조준, 연속 사격 후 복귀, 이동·점프 중 사격, 실행 오류를 확인한다. 체감 적정성은 실제 비교가 필요하다.
