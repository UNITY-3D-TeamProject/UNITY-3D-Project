# 플레이어 아래→위 생성 연출: 조사·계획 검토

## 요청과 진행 범위

- 사용자 목표: 현재 Showcase의 `13.Gravity Angel Dust Dissolve` 오른쪽 모델 소멸 연출을 역방향으로 활용해 `Assets/Test/TestScene.unity`의 Player에 생성 연출을 적용한다.
- 이번 단계는 조사·계획 수립부터 다시 진행하는 것이다. 구현은 시작하지 않았다.
- 사용자는 이 프로젝트 관련 파일을 외부 Claude 모델 서비스에 전달해 조사·계획·구현·수정하는 것을 상시 승인했다. Codex·Claude 전역 지침과 프로젝트 개인 설정에 기록했다. 데이터 전송 승인과 구현 범위 승인은 구분한다.

## 참여와 실제 진행

- Claude Code Opus: 관련 파일과 실행 중인 Unity를 읽기 전용으로 조사하고 최초 계획을 반환했다. Codex 검토 후 수정 계획을 작성했다.
- Codex: 요구와 제약 전달, 계획 검토, 관련 코드 근거 확인, 씬·변경 상태 확인 및 이 요약 작성을 담당했다.
- 중계기의 스트리밍/완료 응답 불일치로 조사 호출 1회와 보완 조사 호출 1회가 중단됐다. 중단된 호출을 조사 완료나 합의로 취급하지 않았다.
- 최종 수정 계획은 완료된 최초 조사와 Codex가 직접 확인한 코드 근거를 전달해 도구 없이 작성하도록 요청했고 정상 수신했다. 보완 조사가 필요한 내용은 확인된 사실로 바꾸지 않았다.

## Claude의 최초 조사 결과

- 오른쪽 모델은 `Statue`, 왼쪽 모델은 `PlayerModel (1)`이다. 오른쪽은 Plane 마스크 위치를 위에서 아래로 이동시키며, 왼쪽은 Ellipse 크기를 바꾸는 다른 연출이다.
- 오른쪽 연출은 `INab.Common.InteractiveEffect`, INab Burn 셰이더와 `Gravity Angel Dust Dissolve.vfx`를 사용한다. 원본 진행은 6초·선형이다.
- `ReverseEffect()`는 파티클을 끄므로, `PlayEffect()`의 마스크 이동 방향을 반대로 구성하는 접근을 제안했다.
- 테스트 Player에는 본체 SkinnedMeshRenderer(Body/Lens), 무기 MeshRenderer 2개와 PowerPod가 있다. 기존 Robot 셰이더는 INab 마스크 속성을 지원하지 않는다.
- 원본 Mike FBX는 Read/Write가 꺼져 있고 INab Readme는 VFX 메시 샘플링에 Read/Write를 요구한다. 원본 importer 변경 없이 사용할 대체 베이커 경로는 확인되지 않았다.

## Codex 검토와 반영

- **M1 — 원본 importer 영향:** 원본 FBX 설정 변경은 테스트 밖 사용처에 영향을 줄 수 있다. 테스트 전용 모델 사본과 대체 베이커 경로를 대안으로 제시했다. 수정 계획에서는 원본 importer 변경을 기본안에서 제외했다. 사본의 리그 호환성과 샘플링은 미검증이다.
- **M2 — 전체 렌더러 동기화:** 단일 Renderer 참조만으로 본체·렌즈·장비 처리 범위가 불명확했다. Codex가 `InteractiveEffect.cs`에서 materials 전체에 공통 world mask를 전달하는 것과, instanced material 모드가 목록을 단일 Renderer 슬롯으로 다시 채우는 것을 직접 확인했다. 독립 재질 사본 목록 유지 또는 Renderer별 effect 동기화를 상세 설계에서 확정해야 한다.
- **M3 — 외형 변경 선택:** INab 재질 영구 교체 시 기존 외형이 바뀐다. 이를 사용자가 허용한 것으로 간주하지 않고, 임시 교체 후 복원·영구 교체·셰이더 사본 통합을 선택지로 정리했다.
- 적용 대상은 사용자가 지정한 TestScene Player 인스턴스로 유지한다. 원본 Player와 ThirdParty 자산을 기본 변경 대상으로 삼지 않으며 Angel Dust를 기본안에서 제거하지 않는다.

## 사용자 선택 대기

| 항목 | 추천 | 다른 선택과 차이 |
|---|---|---|
| 외형 | 생성 중 INab 재질 사본 사용 후 원본 복원 | 영구 교체는 단순하지만 외형 변경. Robot 셰이더 사본 통합은 일관성이 좋지만 작업 범위 증가 |
| VFX 샘플링 | 테스트 전용 모델 사본에 Read/Write 적용 | 원본 importer를 바꾸지 않는 대체 베이커는 지원 확인 전 채택 불가 |
| 파티클 범위 | 본체에 Angel Dust, 렌즈·장비는 공통 마스크로 생성 | Renderer별 VFX는 장비에도 파티클이 나오지만 비용·샘플링 조건 증가 |
| 테스트 코드 위치 | Assets/Test에 격리하는 예외 | 기본 스킬은 자체 C#을 Assets/_Project/Scripts 아래에 요구하므로 예외 승인 필요. 추적 코드에서 미추적 INab을 직접 참조하면 배포 환경 의존성 문제 발생 가능 |

- 기존 초안의 `Assets/Test/SpawnDissolve/`는 테스트 재질·모델·코드 격리 위치 후보다. 아직 생성하지 않았다.
- 위 선택 후 실제 변경 파일, 초기 숨김·완료 복원 순서, 마스크 동기화, 재질·모델 사본 경로를 상세 설계로 확정한다.
- 높이는 추정값을 확정하지 않고 본체·렌즈·장비 전체 bounds를 확인해 산출한다. 시간·곡선은 원본 6초·선형을 기본 후보로 두며 변경 시 사용자 확인이 필요하다.

## 실제 검증과 미검증

- 이번 조사·계획 단계에서는 코드·에셋·씬·importer를 수정하지 않았다. 기존 추적 파일 변경 목록에 추가 제품 변경이 없는 것을 확인했다.
- 현재 Showcase는 정지 상태이며 dirty=false다. TestScene 구현·컴파일·Play 검증은 하지 않았다.
- Plane의 가시 영역 부호, 아래→위 진행에서 Angel Dust의 시각 결과, 실제 마스크 높이, 모델 사본의 스킨·VFX 샘플링, 임시 재질 복원 순간의 외형 전환은 구현 시 검증해야 한다.
- 원문은 현재 채팅 옆 터미널에 표시하며 이 파일에는 요약만 저장했다.
