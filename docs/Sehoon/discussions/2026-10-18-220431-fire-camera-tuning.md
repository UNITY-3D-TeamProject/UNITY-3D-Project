# 사격 카메라 피드백 조정·적용

## 목적과 권한

- 가볍게 즐기는 플랫포머 + TPS에서 발사감과 차지샷 구분을 남기면서 과한 카메라 움직임을 줄인다.
- 사용자가 수치 선택·반복 테스트·명령·적용을 Codex에게 명시적으로 위임했다. 앞선 A/B 선택 대기 상태를 해소한 후 진행했다.
- 앞선 설계 협의: [사격 카메라 피드백 조정 설계](2026-10-18-215121-fire-camera-feedback.md).

## 역할과 실행

- Claude Code Opus: 앞선 대안 비교에서 셰이크만 절반으로 줄이는 A를 추천했다. 이는 테스트 전 추천이었다.
- Codex: Unity 실행 비교·수치 선정·구현 코드 검토 및 실행·diff 리뷰·저장 후 재실행 검증을 수행했다.
- Claude Code Sonnet: 확정된 3개 직렬화 값만 저장·재조회하는 Unity eval 코드를 작성했다. Codex가 검토 후 연결된 Editor에서 실행했다.
- 첫 Sonnet 도구 사용 호출은 중계기의 스트리밍/완료 응답 불일치로 중단됐다. 해당 호출 직후 프리팹 미변경을 확인했고 완료로 간주하지 않았다. 새 터미널 연결 검증을 거쳐 도구 없이 코드 작성만 요청한 재시도는 정상 완료됐다.

## 비교 결과와 결정

정지한 플레이어에서 각 사격 직전 카메라 정면 10m의 기준점을 정하고, 사격 후 기준점의 세로 viewport 이동 최댓값을 측정했다. 각 후보의 일반/차지 × 비조준/조준 4조합, 총 16개 조건을 비교했다. 표의 세기 값은 DefaultVelocity.y의 절댓값이다.

| 후보 | 세기 | 지속시간 | 차지 피치 | 비조준 차지 기준점 이동 | 조준 차지 기준점 이동 |
|---|---:|---:|---:|---:|---:|
| 기존 | 0.5 | 0.20초 | 3도 | 화면 높이 3.735% | 3.010% |
| A | 0.25 | 0.20초 | 3도 | 3.060% | 2.676% |
| B | 0.25 | 0.20초 | 2도 | 2.166% | 1.774% |
| 최종 선택 | 0.20 | 0.12초 | 1.5도 | 1.698% | 1.385% |

- A는 위치 셰이크를 절반으로 줄여도 피치 영향이 남아 차지샷의 전체 기준점 이동 감소가 제한적이었다.
- 최종 후보는 비조준 차지 기준점 이동이 기존보다 약 55% 작았고 잔여 움직임도 짧았다. 일반샷보다 차지샷이 크고 조준 중에는 줄어드는 기존 관계를 유지해 게임 방향에 적합한 값으로 선정했다.
- 일반샷 배율 0.2, 조준 배율 0.5, 복귀 속도 20도/초, Uniform/Bump 형태는 유지했다. 따라서 피치 반동은 비조준 일반 0.3도/차지 1.5도, 조준 일반 0.15도/차지 0.75도다.
- 이는 비교한 후보와 아래 검증 범위에서의 선택이며 모든 환경에서 체감상 유일한 최적값임을 증명한 것은 아니다.

## 실제 변경

- `Assets/_Project/Prefabs/Player/Player.prefab`의 LookPrefab 중첩 인스턴스에만 다음을 저장했다.
  - `CinemachineImpulseSource.DefaultVelocity.y`: -0.5 → -0.2
  - `ImpulseDefinition.ImpulseDuration`: 0.2 → 0.12
  - `PlayerBaseCamera._recoilPitch`: 3 → 1.5
- Unity의 LoadPrefabContents/SerializedObject/SaveAsPrefabAsset/UnloadPrefabContents를 사용했다. 저장 후 다시 로드해 3값을 검증했다.
- diff는 기존 override 값 1개 변경 및 override 2개 추가뿐이다. LookPrefab 원본과 C#에는 변경이 없다. git 조작은 하지 않았다.

## 검증과 한계

- 실제 Play 모드 프레임 증가를 확인했다. 최신 Unity CLI 1.0.0-beta.13과 Unity 6000.4.8f1을 사용했다.
- 선택값으로 Input Actions를 통한 일반/차지 × 비조준/조준 4조합의 사격 이벤트와 반동을 확인했다.
- 60FPS 제한 입력 테스트에서 연속 일반샷 14발을 확인했고 반동이 0으로 복귀했다. 이동·점프 사격에서 발사 시 실제 수평 이동 약 1.5~1.9m, 높이 약 1.4~1.5m를 확인했다.
- 입력 테스트의 연속 차지 한 조건은 기대한 차지 발사로 인정할 수 없어, 실제 Fire.TryExecute/Stop 경로로 별도 재검증했다. 30FPS 제한에서 비조준/조준 각각 연속 차지 2발이 발생하고 피치 최대 1.5도/0.75도 및 최종 0 복귀를 확인했다.
- 첫 임시 입력 드라이버는 버튼의 float delta 사용 오류로 실패했다. 프로젝트에 설치된 입력 명령의 StateEvent/WriteValueIntoEvent 방식으로 바꿔 재검증했고 임시 콜백을 제거했다. 게임 코드 변경으로 처리하지 않았다.
- 저장 후 Play 모드를 새로 시작해 새 플레이어가 최종 3값과 유지 대상 배율·복귀 속도를 불러오는 것을 확인했다. 저장된 프리팹에서 일반 0.3도, 조준 차지 0.75도와 최종 반동 0 복귀를 추가 확인했다.
- 수정된 입력 테스트 이후 및 저장 후 검증 구간에는 신규 error/exception 로그가 없었고 컴파일 실패 플래그도 false였다. 이전 임시 테스트 오류와 기존 로그는 지우지 않았다.
- `git diff --check`를 통과했다. 테스트한 씬은 로비이며 전체 스테이지 플레이·빌드·사람의 체감 평가는 하지 않았다.
- 테스트는 메모리에서 실행했고 새 테스트 스크립트·에셋을 추가하지 않았다. 종료 후 Play 모드·runInBackground·프레임 설정을 원래 상태로 복구했으며 로비 씬은 dirty가 아니다.
