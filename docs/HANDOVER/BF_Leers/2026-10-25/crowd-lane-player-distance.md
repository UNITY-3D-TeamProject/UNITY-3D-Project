# 로비 군중: 추가 최적화 조사와 먼 레인 스폰 제한 (2026-10-25)

## 1. 작업 요약 및 방법
- 질문: LOD(경로 계산 주기 분산) 말고 군중 최적화로 할 수 있는 것이 있는가?
- 에디터 Play, Game 뷰 최대화, 매 프레임 `timeScale=1` 강제(로비가 시작 시 0으로 되돌려 군중이 멈춘 채 재지는 것을 막음), `runInBackground=true`. 구성마다 120프레임 워밍업 후 400프레임 평균. 측정은 `unity-editor-mcp` eval 의 `EditorApplication.update` 콜백으로 했고 원본은 `Temp/` 에 저장 후 삭제했다.
- 측정 결과(군중이 움직이는 상태, 인원이 45→83명으로 늘어나는 중이라 같은 인원 기준 보간값):
  - 인원당 프레임 비용 약 0.043ms (45명 9.96ms → 83명 11.58ms).
  - 군중 그림자 끄기 약 -0.2ms, Animator 끄기 약 -0.2ms (둘 다 측정 오차 수준), 렌더러 끄기 약 -0.6ms, `CrowdController` 끄기 약 -1.0ms (메인 스레드 -1.2ms). GPU 시간은 군중과 무관하게 약 6.5ms 로 일정.
  - 설정 확인: `Physics.autoSyncTransforms=false`, 보행자 Animator `CullUpdateTransforms`, 차량은 Animator 없음, 그림자 거리 40m.
  - FBX: `LilRobot.FBX` 의 `Optimize Game Objects` A/B → `Animators.Update` 67명 0.240 vs 0.248ms (차이 없음, 프리팹이 본 22개를 이미 저장해 인스턴스 변환이 그대로). 임포트 경고(이름 중복)만 늘어 원래대로 되돌림(`False`). 보행자 Animator 비용은 1명당 약 4µs.
  - 차량 삼각형: Car 약 3.9만, Car_2 약 1.5만, **Car_3 약 16.7만**(바퀴 하나 2.4만). 현재 GPU 에서는 비용이 작았으나 저사양 GPU 에서 부담될 수 있음.
- 구현(사용자 결정: 먼 레인은 새로 꺼내지 않기 / 50m / 플레이어 기준): `CrowdLane._playerSpawnDistance`(기본 50, 0 이하면 끔), `IsPlayerNearLane()`. 자세한 규칙은 intent-017.
- 실행자: Claude 직접. 예외 사유 = 이 PC 에 Codex CLI 미설치.

### 추가 (같은 날): 위치별 측정 후 25m + `_count` 감소 적용 (사용자 결정)
- 50m 는 시작 위치(높이 16m)에서만 효과가 컸고 지상 로비 중심에서는 76~83명, 78~88 FPS 로 거의 효과가 없었다(사용자도 70~90 FPS 로 확인). 레인 9개 중 8개가 중심에서 24m 이내.
- 적용: 코드 기본값 `_playerSpawnDistance` 50 → 25. `Map_1_Lobby` 레인 9개의 `_playerSpawnDistance`(씬에는 50 이 직렬화돼 있어 직접 바꿈)=25, `_count` 합계 132 → 51(표는 intent-017). 씬 변경은 에디터 MCP 로 했고 **씬은 저장하지 않았다(미저장 상태)**.
- 최종 측정(Game 뷰 최대화, 위치당 90초 적응 후 1배속 300프레임): 시작 위치 6명 8.56ms(116.9 FPS) / 로비 중심 40명 9.59ms(104.2 FPS) / `Pedstrian_Lane_7` 중간 33명 9.52ms(105.0 FPS).

## 2. 결정 사항
- 군중 줄이기는 동시 활성 인원을 줄이는 방향. 방식은 "플레이어에게서 먼 레인은 새로 꺼내지 않기"(이미 나온 개체는 끝에서 반납), 기준 50m, 기준 대상은 플레이어.
- 레인과의 거리는 레인의 모든 스플라인 중 가장 가까운 점 기준(시작점 기준이 아님). 플레이어가 없으면 제한하지 않는다.
- `LilRobot.FBX` 임포트 설정은 건드리지 않는다(`ThirdParty` 라 Git 에 올라가지 않음).

## 3. 현재 상태 및 이슈
- 리컴파일 통과(`gate.cjs check recompile`, 최종 코드 기준). 게이트 루프 미실행, 커밋 전.
- 효과(플레이어 시작 위치, 끔 vs 50m): 84명 11.44ms(87 FPS) → 29명 9.23ms(108 FPS).
- **육안 확인 안 함**: 비워진 먼 인도에 다가갈 때 한동안 비어 보이는지(긴 인도는 가득 차기까지 수십 초), 멀리 보이는 거리가 한산해 보이는지. 특히 시작 위치(높이 16m)에서는 25m 제한 때문에 보행자가 0명이고 차량만 6대라 허전할 수 있다.
- **`Map_1_Lobby` 는 저장 전**: 레인 `_count`·`_playerSpawnDistance` 변경이 에디터에 반영돼 있고 씬이 미저장(dirty)이다. 씬에는 이 작업 이전부터 있던 미저장 변경(사용자 작업)도 섞여 있을 수 있으니 저장 전 확인한다.
- 에디터 기준 수치다. 빌드는 측정하지 않았다.
- 씬 `Map_1_Lobby` 는 시작 전부터 수정 상태이고 이 작업에서 저장하지 않았다. 새 필드는 기본값(50)이 적용되므로 씬 수정은 필요 없다.
- 첫 측정 두 번은 버렸다: `timeScale` 이 0 으로 돌아가 군중이 멈췄고, 한 번은 `runInBackground` 가 꺼져 프레임이 1.6초였다.
