# intent-003 판단부/실행부 분리 기준 재정립

## 1. 작업 요약 및 방법
- 기존 intent-003에는 "BT는 컴포넌트를 호출만 한다"는 규칙만 있고 근거가 없었다. Action 클래스만으로도 서로 의존하지 않고 재사용할 수 있지 않느냐는 질문에서 출발해, 무엇을 컴포넌트에 두고 무엇을 노드에 둘지 기준을 다시 세웠다.
- `docs/intent/intent-003-enemy-ai.md`의 "판단부와 실행부 분리" 절을 새 기준으로 교체했다. 열린 질문 5번에는 한 줄을 보완했고, 8번을 새로 추가했다.
- 문서만 수정했다. 코드는 건드리지 않았고 커밋도 하지 않았다.

## 2. 결정 사항
- **실행 모델:** Action은 컴포넌트에 명령만 걸고, 실제 실행은 컴포넌트의 `Update`가 매 프레임 한다. 노드가 바뀌어도 `CharacterMotor.Move()` 호출(중력, 외부 변위 포함)과 `nextPosition` 동기화가 끊기지 않게 하기 위해서다.
- **분류 기준:** 아래 중 하나라도 해당하면 컴포넌트에 둔다. 셋 다 아니면 노드 안에 직접 쓴다.
  - A. 노드 수명보다 오래 사는 상태나 매 프레임 처리가 있다
  - B. BT 밖에서도 불린다
  - C. 여러 노드가 공유하는 계산이나 캐시다
- **회전:** `EnemyMotor`만 회전시킨다. 노드는 `SetLookTarget`/`ClearLookTarget`으로 바라볼 대상만 바꾼다. 기존의 `FaceTarget()`은 없앴다.
- **노드 안에 쓰는 것:** 블랙보드 기록 Action 4개, 추격·귀환·대기, 경로 실패 처리, Condition(사거리, 추격 포기, 리쉬, 수직 대응).

## 3. 현재 상태 및 이슈
- `EnemyCombat`의 책임 범위는 **미정**이다. 전투 담당 팀원과 `AttributeSet`에 어떤 값을 넣을지 회의한 뒤 확정한다. 열린 질문 5번도 같은 이유로 미해결이다.
- 선딜 대기 타이머를 공격 Action에 둘지도 `EnemyCombat`이 확정된 뒤에 정한다.
- 열린 질문 8번(신규): 노드가 AI 스탯 SO를 어떻게 읽을지 정해야 한다. (a) 블랙보드에 SO 참조를 둔다, (b) 컴포넌트를 통해 읽는다. (a)를 택하려면 Behavior 블랙보드가 ScriptableObject 타입 변수를 지원하는지 확인해야 한다.

## 4. 다음 할 일
- 전투 담당과 회의해 열린 질문 5번과 `EnemyCombat` 책임을 확정한다.
- Behavior 패키지에서 ScriptableObject 블랙보드 변수 지원 여부를 확인해 열린 질문 8번을 해결한다.
- `AI/Core`, `AI/Enemy` 폴더에 `EnemyMotor`/`EnemySensor` 구현을 시작한다. 이 둘은 `EnemyCombat`에 의존하지 않으므로 먼저 진행할 수 있다.
