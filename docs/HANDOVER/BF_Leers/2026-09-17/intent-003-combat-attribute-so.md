# intent-003 열린 질문 5 반영 — 전투 속성 SO 결정

## 1. 작업 요약 및 방법
- 전투 담당 팀원과 회의한 결과를 `docs/intent/intent-003-enemy-ai.md`의 열린 질문 5번에 반영했다.
- 5번에 "해결 (2026-09-17)" 항목을 추가했다. 기존 "남은 확인" 1~3번은 지우지 않고 해결 표시만 붙였다.
- "판단부와 실행부 분리" 표의 `EnemyCombat`/`EnemyHealth` 행과 "값 소유권" 절도 같이 갱신했다.
- 문서만 수정했다. 코드와 에셋은 건드리지 않았고 커밋도 하지 않았다.

## 2. 결정 사항
- `SOAttributeData` 에셋을 플레이어용과 적용 두 종류로 나눈다. 적용은 타입마다 복제한다.
- 전투 중 안 바뀌는 상수(공격 범위, 선딜)도 같은 SO에 넣는다. 별도 typed SO는 만들지 않는다.
- 같은 의미의 속성은 플레이어와 적이 같은 이름을 쓴다(예: `"Hp"`).
- 적 속성 목록(프로토타입): `Hp`, `MaxHp`, `AttackPower`, `AttackCooldown`, `AttackRange`, `AttackWindup`. `Defense`는 데미지 공식이 정해질 때까지 뺀다. AI 판단 값(감지 거리 등)은 AI 스탯 SO에 둔다.
- 공격 간격은 쿨다운 방식이고 속성 이름은 `AttackCooldown`이다.
- `IDamageable`은 만들지 않는다. `EnemyCombat`은 `SOAttributeEffect.Apply(플레이어, 자기)`로 공격한다. `EnemyHealth`는 `"Hp"` 변경 콜백으로 사망을 처리한다.

## 3. 현재 상태 및 이슈
- 문자열 키라서 오타를 컴파일러가 못 잡는다. 완화책(속성 이름 상수 클래스 등)은 구현 단계에서 정한다.
- 아직 확인할 것이 두 가지 남아 있다. 쿨다운 기준 시점(발동 시각인지 적중 시각인지)과 몹 타입별 선딜 유무다. 선딜 타이머를 공격 Action에 둘지도 이 답에 따라 정한다.
- 열린 질문 8번(AI 스탯 SO 접근 방식)은 여전히 미해결이다.
