# Singleton 주석 검토

## 작업 요약 및 방법
- 사용자가 제공한 Singleton<T> 코드와 주석을 대조하고 Unity 공식 API 문서에서 검색 범위, Awake 호출 순서, DontDestroyOnLoad 조건을 확인했다.

## 결정 사항
- 주석의 전체 흐름은 맞다. 정확한 상속 계층의 Behaviour, T별 정적 참조, 기본 검색의 비활성 GameObject 제외, DontDestroyOnLoad의 루트 조건을 보완하도록 안내한다.
- Awake 이전에도 기존 객체를 찾을 수 있다는 설명 및 프리팹 참조가 자동 생성 객체에 복사되지 않는다는 설명은 유지한다.

## 현재 상태 및 이슈
- 후속 질문에서 HEAD와 작업 트리의 Singleton.cs를 비교했다. 기존 코드는 Awake에서 _instance가 있으면 자신까지 삭제했고 OnDestroy는 없었다. 현재 변경은 미커밋 상태다.
- 변경의 핵심 이유는 Instance가 Awake 전에 자신을 찾아 등록했을 때 자기 자신을 중복으로 오인해 삭제하는 문제를 막는 것이다. OnDestroy 추가는 등록된 객체가 파괴될 때 참조를 명시적으로 정리한다.
- 게임 코드 수정이나 실행 테스트는 하지 않았다. 검토 기록과 인수인계 목차만 추가했다.
- 주석 5번의 중복 번호를 확인했다.
