# AudioManager 로직 검증

## 작업 요약 및 방법
- 사용자 요청에 따라 AudioManager·SOAudioData·믹서·SO·프리팹과 SettingsPresenter, GameManager, SceneLoader, LoadingScreen을 검토했다. 게임 코드와 에셋은 수정하지 않았다.
- CLAUDE.md, 프로젝트 기본 스킬, 응답·코딩 규칙, intent-038과 이전 오디오 검토 기록을 확인했다. 영구 싱글톤과 BGM 표 설계는 과거 기록이며, 현재 확정된 씬 단위 구조를 기준으로 판단했다.
- 사용자 승인 후 Unity MCP가 사용하는 CLI를 `unity self-update`로 1.0.0-beta.12 → beta.13으로 업데이트하고 버전을 확인했다. MCP 서버 패키지·Unity 에디터·프로젝트 패키지를 교체한 작업은 아니다.
- TestScene Play에서 임시 AudioManager 프리팹과 메모리에 생성한 클립·SO를 사용했다. 리플렉션으로 내부 상태를 읽고, 임시 C# 검증 파일은 OS 임시 폴더에서 run_script로 메모리 컴파일했다.

## 정상 확인
- 컴파일 상태 `up_to_date`, `failed=false`, `compilationFailed=false`, 오류 배열 비어 있음. 검증 중 스크립트 변경이 없어 새 프로젝트 컴파일은 필요하지 않았음.
- 3D 소스 16개 생성, 지정 위치·spatialBlend=1·클립·피치 설정, 6초 클립의 종료 시각 기록, 동일 프레임 중복 차단.
- Master=0 → -80dB, Bgm=0.5 → -6.0206dB, 볼륨 입력 2 → 1로 제한.
- BGM/UI ignoreListenerPause=true, 3D=false. 실제 Time.timeScale=0·AudioListener.pause=true에서 scaled time은 멈추고 BGM 시간은 약 0.25초 진행함.
- BGM 3곡 순서 0→1→2→0, 셔플 다음 곡 선택 100회에서 현재 곡 재선택 0회, 단일 곡 loop=true.
- 0.4초 클립 3개·페이드 0으로 시작해 약 0.56초 후 다음 곡(index=1) 자동 전환.
- Additive 씬 로드 처리 경로를 직접 호출하면 곡 넘기기가 차단되고 약 0.3초 페이드 후 소스가 정지하며 volume=0. 실제 씬 전환은 수행하지 않았음.
- 현재 Audio SO 6개에 클립 참조 누락 0개.
- 피치 배율 6을 전달했을 때 실제 source.pitch도 6으로 유지됨. 상한 3으로 잘려 수명 계산이 틀린다는 추정은 이 에디터에서 성립하지 않아 문제로 보고하지 않음.

## 현재 상태 및 이슈
1. **[P2] 재생 실패한 SFX가 중복 제한에 기록됨** — AudioManager.cs 190~195, 300행. TryPickClip이 먼저 시각을 기록하고 나서 빈 소스를 찾는다. 모든 소스의 종료 시각을 미래로 둔 상태에서 호출하면 재생하지 않았어도 딕셔너리에 기록된다. 바로 소스 하나를 비운 뒤 같은 클립으로 재요청해도 제한에 걸려 빈 슬롯을 사용하지 못함을 확인했다. 실제 할당·재생 성공 후 시각을 기록하는 흐름이 필요하다.
2. **[P2] UI에도 50ms 중복 제한 적용** — AudioManager.cs 173행. PlayUi가 SFX와 같은 TryPickClip·딕셔너리를 사용한다. UI 재생 후 해당 클립이 제한 딕셔너리에 추가됨을 확인했다. 빠른 UI 요청이 누락되고 같은 클립을 UI·SFX가 공유하면 서로 차단한다. intent-038의 1단계 제외 항목인 'UI 연타 제한'과 어긋난다. UI의 클립 선택과 SFX 중복 제한을 분리하는 것이 적절하다.
3. **[P2] 짧은 BGM에서 긴 페이드인이 무음 구간을 만듦** — AudioManager.cs 409~417행. 곡의 재생 종료를 검사하기 전에 페이드인 전체를 기다린다. 0.05초 클립 2개·FadeIn=0.6초·FadeOut=0으로 시작하면 약 0.23초 후에도 index=0, isPlaying=false로 다음 곡이 시작되지 않았다. 클립은 끝났지만 페이드인 코루틴이 남아 있다. 남은 재생 시간에 맞춰 페이드 시간을 제한하거나 재생 종료 시 페이드를 끝내야 한다. 현재 긴 BGM 에셋에서 발생했다는 의미는 아니다.
- 이전 검토의 '서로 다른 BGM 전환 중 Skip이 초기화를 건너뛰는 문제'는 해당 전환 경로가 현재 코드에서 제거되어 적용되지 않는다.

## 결정 사항 및 한계
- 요청 범위는 검증이므로 수정·커밋하지 않았다. 설계 변경이나 새 intent를 만들지 않았다.
- 실제 청취, 운영 씬 전체 이동, 설정창 클릭 및 PlayerPrefs 디스크 저장·재실행 검증은 수행하지 않았다.
- 검증 도중 에디터가 백그라운드에서 틱을 멈춰 MCP 메인 스레드 타임아웃이 한 번 발생했다. auto-tick 조정 후 검증을 완료했다. 이를 오디오 코드 오류로 분류하지 않았다.
- Play 종료, 임시 오브젝트 0개, listenerPause=false, runInBackground=false 복원을 확인했다. 씬 저장은 하지 않았다. 다른 작업에서 변경 중인 UI·프로젝트 설정·문서는 보존했다.
