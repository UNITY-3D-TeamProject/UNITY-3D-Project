# 단일 스포너와 여러 복귀 지점 관리 비교

- 작업 요약: 타입별 PlayerSpawner를 여러 개 배치하는 방식과 하나의 PlayerSpawner가 여러 위치를 관리하는 방식을 비교했다. 런타임 코드는 변경하지 않았다.
- 방법/접근: 현재 요구사항은 저장된 앱 씬 값에 따라 플레이어 한 명의 생성 위치를 선택하는 것이므로 단일 스포너를 추천했다.
- 제안 사항: 로비에 PlayerSpawner 하나와 기본 위치 및 앱별 복귀 위치 Transform을 둔다. 스포너 Inspector에 앱 씬 값과 해당 Transform의 연결을 설정하고, 보관값이 없으면 기본 위치를 선택한다. 생성 완료 후 GameManager의 보관값을 비운다.
- 현재 상태 및 이슈: 사용자 선택 전의 설계 제안. 여러 스포너 방식도 가능하지만 모든 스포너가 같은 보관값을 읽고 타입 조건을 검사해야 하며, 등록 중복 시 중복 생성과 기본 스폰 처리 분산을 고려해야 한다. 스포너마다 값 소비를 처리하면 다른 스포너의 판정 전에 값이 비워지는 실행 순서 문제도 생길 수 있다.
- 다음 할 일: 구조 확정 및 구현 요청 시 현재 PlayerSpawner의 생성 위치 선택만 필요한 범위로 확장한다.
