# 씬 전환 이벤트의 두 방식과 담당자별 책임

- 작업 요약: 공용 씬 enum 전달 방식과 EStageType 직접 전달 방식을 비교하고 담당자별 작업 범위를 정리했다. 런타임 코드는 수정하지 않았다.
- 방법/접근: 씬 로딩의 책임과 스테이지 판정·복귀 기록의 책임을 기준으로 의존성을 비교했다.
- 제안 사항: 공용 ESceneType을 씬 식별자로 사용한다. 씬 전환 담당자는 ESceneType→실제 씬 이름/경로 변환과 전환 직전 Action<ESceneType> 이벤트 호출, 실제 로딩을 맡는다. GameManager는 이벤트 구독·해제, 능력치 저장, ESceneType→EStageType 매핑과 SpawnStage 갱신을 맡는다. ESceneType은 예시 이름이며 실제 공용 타입과 인터페이스는 담당자와 확정해야 한다.
- 결정 사항: 씬 전환 담당자가 EStageType을 알 필요가 없는 첫 번째 방식을 추천한다. 두 enum을 연결하는 책임은 GameManager에 둔다. 두 번째 방식도 가능하지만 씬 전환 쪽이 스테이지 구분까지 알아야 하며, 비스테이지 씬을 표현하려면 EStageType? 등의 표현이 필요하다.
- 현재 상태 및 이슈: 목적지가 로비 등 비스테이지 씬이면 SpawnStage를 덮어쓰지 않는다. 로비 스폰 완료 후 ClearSpawnStage가 소비한다. enum 항목과 실제 씬 목록, 전환 이벤트는 구현되지 않은 상태다. 이번 답변은 설계 정리이며 컴파일·실행 검증은 하지 않았다.
- 다음 할 일: 공용 씬 enum과 전환 전 이벤트 형식을 담당자와 합의하고 각각의 변환 및 이벤트 연결을 구현한다.
