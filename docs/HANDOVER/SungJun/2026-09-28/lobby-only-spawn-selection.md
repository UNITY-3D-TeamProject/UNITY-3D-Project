# 로비 전용 위치 선택과 공용 플레이어 생성

- 작업 요약: 로비에는 여러 복귀 지점, 스테이지에는 하나의 생성 위치가 있다는 사용자 설명을 기준으로 현재 코드를 확인하고 변경 방향을 정리했다. 런타임 코드는 변경하지 않았다.
- 방법/접근: 공용 PlayerSpawner에 로비 여부를 명시하고, 로비에서만 GameManager의 보관값과 앱별 Transform 목록을 사용해 위치를 선택하는 최소 변경안을 제안한다. 스테이지에서는 현재처럼 스포너 자신의 위치와 방향을 사용한다.
- 제안 사항: GameManager의 복귀 보관값은 EStageType?으로 두어 기존 enum에 없는 '값 없음'을 null로 나타낸다. 현재 enum의 기본값인 Tutorial을 '값 없음'으로 취급하지 않는다. 스테이지 진입 전 복귀 값을 보관하고, 로비행 전환에서는 유지한다.
- 현재 상태 및 이슈: 스테이지 PlayerSpawner는 복귀 기록을 소비하거나 비우면 안 된다. 로비에서 생성 완료 후에만 기록을 비운다. 로비용 위치 선택 분기를 제외한 Instantiate 및 RegisterPlayer 흐름은 공통으로 유지한다. 실제 전환 이벤트는 아직 연결되어 있지 않다.
- 다음 할 일: 구현 요청 시 GameManager의 보관·조회·초기화와 PlayerSpawner의 로비 선택 분기를 추가하고 실제 전환 이벤트 형식에 맞춰 연결한다.
