# 앱에서 로비로 복귀할 때 스폰 위치 관리 논의

- 작업 요약: 첨부 이미지의 질문을 로비 복귀 위치에 대한 설계 질문으로 해석하고, 현재 PlayerSpawner와 GameManager/Singleton 흐름을 확인했다. 런타임 코드는 변경하지 않았다.
- 방법/접근: 로비의 PlayerSpawner는 하나 유지하고, 앱 입구별 복귀 위치를 빈 Transform으로 배치한다. 앱 진입 전에 복귀 지점 ID를 씬 전환 후에도 유지되는 객체에 보관하고, 로비로 돌아왔을 때 새 씬의 ID별 위치를 선택해 생성하는 방식을 제안했다.
- 변경된 파일: 이번 논의 기록과 HANDOFF_POINTER.md.
- 제안 사항: 복귀 ID는 전환 담당 객체 또는 현재 유지되는 GameManager가 보관하고, 실제 Transform 참조는 로비 씬 내부에서 관리한다. StageManager의 진행 상태와는 분리한다. 앱마다 입구 하나라면 EStageType으로 구분할 수 있고, 같은 앱의 입구가 여러 개면 별도 지점 ID가 필요하다.
- 현재 상태 및 이슈: 설계 제안이며 구현은 미착수. 현재 PlayerSpawner는 자신의 위치에서 무조건 생성하므로 여러 스포너를 배치하면 각각 플레이어를 생성한다. 로비 최초 진입의 기본 위치, ID 누락 시 기본 위치 및 로그, 복귀 스폰 후 ID 소비, 진입 트리거 바깥의 복귀 위치를 구현 시 고려한다.
- 다음 할 일: 구현 요청 시 실제 씬 전환 담당 코드와 입구 구성을 확인하고, 필요한 범위만 연결한다. 왕복 시 해당 입구 앞에 한 명만 생성되는지 검증한다.
