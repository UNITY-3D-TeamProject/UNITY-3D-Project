# Start의 스폰 코드를 재사용 함수로 분리

- 작업 요약: Start 내부의 스폰 코드를 함수로 분리하여 재스폰에서도 호출하면 되는지 확인했다. 런타임 코드는 변경하지 않았다.
- 방법/접근: 기존 Start의 초기화 검사, 위치 선택, Instantiate, RegisterPlayer 및 로비 기록 소비 흐름을 SpawnPlayer라는 public 메서드로 옮기고 Start에서는 해당 메서드만 호출하는 최소 구조를 안내했다.
- 결정 사항: 최초 진입과 사망 후 재스폰에서 같은 생성 함수를 재사용할 수 있다. 로비 여부에 따른 위치 선택과 ClearSpawnStage 호출도 함수 내부에 그대로 유지한다.
- 현재 상태 및 이슈: 사망 처리는 기존 플레이어를 제거하고 재생성 함수를 호출하는 순서로 연결해야 한다. 재스폰 호출자를 이번 논의에서 구현하거나 확정하지 않았고 예시는 컴파일·실행 검증하지 않았다.
- 다음 할 일: 구현 요청 시 기존 Start 본문을 SpawnPlayer로 이동하고 실제 사망 처리 경로에서 호출하도록 연결한다.
