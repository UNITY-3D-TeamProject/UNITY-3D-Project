# 인스타 기획에 필요한 스테이지 진행 로직 검토

- 작업 요약: 사용자가 첨부한 인스타(피드 앱) 기획 이미지 두 장과 현재 FeedApp, StageBase, StagePhaseBase, StageManager를 비교했다. 런타임 코드는 수정하지 않았다.
- 방법/접근: 기획의 실제 상호작용·전투·물리 동작과 목표 진행·완료 판정을 분리하여 각 스크립트의 책임을 정리했다.
- 확인한 기획: 9개 피드 중 미끼게시물 3개를 근거리 상호작용으로 제거한다. 미끼게시물에서 나온 악성데이터는 플레이어에게 날아오며 총으로 제거한다. 해시태그 및 게시글 문구 데이터를 모아 업로드 장치에 넣고 플레이어 피드를 만든다. 기존 6개와 생성한 피드 1개를 합친 7개를 해시태그에 맞는 입구로 보내며 바깥 피드부터 처리하고 플레이어 피드를 마지막에 보내면 성공한다.
- 제안 사항: FeedApp은 미끼게시물 제거 현황, 악성데이터 처리 현황, 데이터 수집·업로드 완료 여부, 피드 분류 성공·순서 및 최종 성공을 관리한다. 각 오브젝트는 삭제·수집·업로드·입구 도착 결과를 알리고, FeedApp이 다음 목표를 활성화하고 완료를 StageManager에 전달한다. 스캔 표시, 입력, 악성데이터 이동·피격, 총, 피드 물리는 해당 기능 컴포넌트가 맡는다.
- 현재 상태 및 이슈: FeedApp.StartStage는 StageProgress를 0으로 초기화하는 코드만 있고 EndStage는 비어 있다. StageManager가 FeedApp의 완료를 전달받는 연결도 없다. 악성데이터의 구체적인 생성 수·생성 종료·완료 조건, 1번과 2번 목표의 진행 관계, 필요한 수집 데이터 목록, 사망 시 목표 초기화 범위는 이미지로 확정할 수 없다.
- 결정 사항: 지금 기획만으로도 앱 내부의 목표 진행과 성공 판정을 담당하는 FeedApp 로직은 필요하다. 별도 대규모 관리 구조를 제안하거나 구현하지 않았다.
- 다음 할 일: 미정인 완료 조건과 재시작 범위를 확정하고 목표별 완료 통지 및 FeedApp→StageManager의 성공 전달 계약을 구현한다. 이번 검토는 이미지 및 정적 코드 확인만 수행했으며 Unity 실행 검증은 하지 않았다.
