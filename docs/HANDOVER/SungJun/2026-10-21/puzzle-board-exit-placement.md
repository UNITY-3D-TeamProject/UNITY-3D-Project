# 숫자 퍼즐 패널을 2라운드 출구 문 앞으로 옮기기 (Map_3_File)

## 작업 요약 및 방법
- 사용자 요청: 출구 칸이 생성할 때마다 바뀌는데, 퍼즐 패널을 2라운드 출구 앞에 놓는다. 사용자가 `Map_3_File`에 패널 하나를 놓는 것을 허락했다.
- 확인한 구조
  - 출구 문(`MazeGate_B`)은 출구 칸 가운데에, 미로와 같은 회전으로 놓인다. 문짝은 로컬 z +2.5(칸 끝)에 있고 폭은 4.6 m다.
  - 패널(`MazePuzzleBoard`)은 폭 약 4.8 m이고 +Z가 문 쪽이다.
- 코드 (Core만 수정)
  - `NumberPuzzleRound`: 찾아 둔 패널을 돌려주는 속성 `Board`를 추가했다.
  - `FileApp`:
    - 인스펙터 값 `_puzzleBoardOffset`(기본 1.5)을 추가했다.
    - `LockMazeGates` 끝에서 `PlacePuzzleBoard()`를 부른다. 2라운드 문 기준 로컬 (0, 0, 1.5)에 문과 같은 회전으로 패널을 옮긴다.
    - 문이나 패널이 없으면(TestScene 등) 아무것도 하지 않는다.
- `Map_3_File`: 루트에 `MazePuzzleBoard` 프리팹 인스턴스를 하나 놓고 저장했다. 위치는 (0, 0, 0)이고, 시작할 때 옮겨진다. 씬 diff는 추가만 있다.
- intent-054에 "변경 (2026-10-21, 패널 위치)"를 추가했다.

## 검증
- 리컴파일했고 에러는 없었다.
- `Map_3_File`을 Play로 3번 확인했다(시드 3개). 출구 문은 `Gate_14_14`, `Gate_14_14`, `Gate_13_14`였고, 3번 모두 패널이 문 기준 로컬 (0.00, 0.00, 1.50)에 놓였다. 회전 차이는 0°였다.
- 패널을 찾았으므로 퍼즐이 준비됐고(`IsReady` true), 아이템 13개에 값 13종이 모두 붙었다. 2라운드 문 트리거는 꺼져 있었다.
- 리셋 버튼(`DamageButton.OnPressed`)을 누르면 목표값이 새로 뽑히고, 13곳 중 12곳의 값이 바뀌었다.
- 퍼즐을 끝까지 풀어 봤다.
  - 정답 조합을 `Interact`로 먹고, 칸 버튼 0·2·4·1·3을 차례로 눌렀다.
  - 결과: 정답 처리, `IsRoundCleared(1)` true, 패널 숨김, 2라운드 문 열림.
- 새 게임 에러는 0개였다. Play 시작 직후 MCP 호출이 시간 초과된 에러 1개만 있었고, 게임과는 상관없다.
- Play 때문에 바뀐 `Pretendard-Bold SDF.asset`은 되돌렸다. 에디터는 다시 TestScene으로 열어 두었다.

## 결정 사항
- 패널은 맵에 하나만 두고, 위치는 `FileApp`이 2라운드 문 기준으로 정한다. Map 스크립트·생성기·문 프리팹은 수정하지 않았다.

## 현재 상태 및 이슈
- 확인하지 않은 것: 실제로 걸어 들어가 보기, 실제 사격으로 칸 맞히기, E 입력, 실제 사망 리셋.
- 확인하지 않은 것: 출구 칸에 옆(동·서)으로 들어올 때 패널이 길을 막는지 육안 확인.
- TestScene은 이번에 Play하지 않았다. 미로가 없어 패널을 옮기지 않는 경로라 동작은 그대로일 것이다.
- 커밋하지 않았다. 작업 전부터 있던 `SOMazeChainSettings_File.asset`, `EditorBuildSettings.asset` 변경은 건드리지 않았다.
