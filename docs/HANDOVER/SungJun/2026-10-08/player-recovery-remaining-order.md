# 플레이어 복구 남은 구현 순서 재확인

- 작업 요약 및 방법: 10월 7일 설계, 10월 8일 통합 Codex 인수인계와 커밋 기록을 현재 Core 코드와 대조했다.
- 현재 상태: StageManager에 라운드 시작 체크포인트 인덱스 배열, 현재 라운드/체크포인트 인덱스와 조회 프로퍼티가 있다. PlayerState에는 씬 전환 저장만 있고, PlayerSpawner의 스테이지 생성 위치는 자신의 transform이다. StageManager는 OnDeath를 구독하지만 사망 시 EndStage와 OnStageFailed를 호출한다.
- 결정 사항: 기존 9단계 순서를 유지한다. 1단계 데이터 구성은 반영됐으며 Inspector 설정 및 Unity 검증은 남았다. 같은 씬에서 기존 플레이어를 재사용하고 사망 시 일반 진행도도 라운드 시작점으로 되돌린다.
- 다음 할 일: 1단계 설정 확인 → 2단계 라운드 HP·배터리 스냅샷 → 3단계 최초 스폰 위치 전달 및 초기 스냅샷 → 4단계 체크포인트 도달 → 5단계 기존 플레이어 이동·상태 초기화 → 6단계 공통 사망 판정·이벤트 → 7단계 라운드 복구 → 8단계 낙하 데미지·생존 복귀 → 9단계 중복 처리 통합 검증.
- 주의 사항: 기존 OnDeath 구독만으로 모든 HP 감소 원인이 연결됐다고 판단하지 않는다. 낙하 데미지 중 사망 콜백이 HP를 복원해도 생존 복귀가 추가 실행되지 않게 한다. 초기 능력치 적용/복원 이후 첫 스냅샷을 저장한다.
- 검증 및 이슈: Core 밖 사망·이동 API, 실제 Inspector 설정은 이번 검토에서 확인하지 않았다. Unity 컴파일 및 Play Mode 검증은 수행하지 않았다.
- 변경된 파일: 이 기록과 HANDOFF_POINTER.md. 게임 코드 변경 없음.
