# 사망 시 플레이어 재사용 검토

- 작업 요약: 최초 생성 이후 StageManager가 기존 플레이어의 위치·상태를 복구하는 방식과 삭제/재생성 방식의 비용을 비교했다.
- 방법: 앞선 Core 검토 결과와 Unity 공식 ObjectPool 문서를 근거로 설명했다. https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/pool/objectpool1
- 권장 사항: 같은 씬에서는 PlayerSpawner가 최초 생성만 담당하고, 사망 시 StageManager가 이동 및 PlayerState의 라운드 스냅샷 복원을 조율한다. 한 명의 플레이어를 유지하는 데 별도 풀은 필요하지 않다.
- 성능: 일반적으로 기존 객체의 위치·상태 복구가 생성/삭제보다 CPU·할당 부담이 적다. 실제 차이는 프리팹 복잡도·복구 처리에 달려 있고 측정하지 않았다. 낮은 사망 빈도에서 성능 차이가 반드시 크다고 단정하지 않는다.
- 주의점: HP·배터리뿐 아니라 사망 플래그, 이동 속도/외력, 애니메이션, 입력/충돌 상태 등 실제 사망 처리에서 바뀐 상태를 복구해야 한다. Core 밖의 실제 부활 계약은 미검토다.
- 범위: 씬 전환으로 플레이어가 파괴되면 새 씬에서 생성이 필요하다. 게임 전체에 영구 플레이어를 도입하는 설계는 포함하지 않는다.
- 변경 파일: 이 기록, HANDOFF_POINTER.md. 런타임 코드 변경 없음.
- 다음 단계: 구현 요청 시 기존 사망 처리가 플레이어를 파괴하는지와 부활/워프 API를 확인한다.
