# 4단계 체크포인트 도달·라운드 갱신 코드 안내

- 작업 요약 및 방법: StageManager, PlayerState, 실제 Player 프리팹의 CharacterController, CharacterMotor 및 기존 Map 체크포인트를 읽고 Unity ComputePenetration 공식 API를 확인했다. 사용자 적용용 코드만 대화로 안내하며 게임 파일은 수정하지 않았다.
- 결정 사항: 스폰 이벤트에서 AttributeSet의 부모 CharacterController를 몸체로 캐싱한다. StageManager.LateUpdate에서 플레이 중·생존 여부와 유효 참조를 검사하고 BoxCollider 영역과 캐릭터 몸체의 겹침을 ComputePenetration으로 판정한다.
- 진행도 규칙: 실제 겹친 체크포인트만 처리하고 일반 진행도는 최대 인덱스를 유지한다. 라운드 진행도는 별도로 판정하여, 일반 진행도보다 낮은 지점이라도 아직 방문하지 않은 다음 라운드 시작점을 실제 밟으면 저장/라운드 갱신이 가능하도록 한다. 다음 라운드의 스냅샷 저장 성공 후 현재 라운드를 갱신한다. 이전 라운드 재접촉은 되돌리지 않고 최초 스냅샷을 덮어쓰지 않는다.
- 설정: 공통 체크포인트 목록은 경로 순서, 라운드 매핑은 중복 없이 증가하는 인덱스로 설정한다. Area는 활성 BoxCollider이며 Is Trigger로 설정하고 RespawnPoint를 연결한다. 이번 감지에는 기존 Map.Gimmicks.Checkpoint 스크립트를 함께 쓰지 않는다.
- 한계: 현재 프레임의 겹침 검사이므로 고속 이동으로 얇은 영역을 완전히 통과하면 놓칠 수 있다. 라운드 진입은 시작 체크포인트 도달 기준이며 월드/목표 초기화는 포함하지 않는다. 후속 낙하·사망 복구 구현 시 복구 중 감지 차단과 처리 우선순위를 추가해야 한다.
- 현재 상태: 코드 안내만 제공. 적용 및 Unity 컴파일·Play 검증 미실시. 사망/낙하 이동 기능은 다음 단계에 남아 있다.
- 확인 기준: C0 최초 스폰 → C1 일반 진행도만 갱신 → C2가 다음 라운드 시작이면 최초 HP·배터리 저장 → C1/C2 재접촉 시 라운드/진행도 역행 및 스냅샷 덮어쓰기 없음.
- 다음 할 일: 사용자 적용 후 검토하고 5단계 기존 플레이어 이동·속도 초기화 API 연결 진행.
