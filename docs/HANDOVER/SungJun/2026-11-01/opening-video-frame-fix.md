# 오프닝 영상 카메라 튐 1프레임 수정

## 작업 요약 및 방법
- 증상: 오프닝에서 주인공이 폰을 떨어뜨리는 장면에서 화면이 1프레임 이상하게 튐.
- 원인: 영상 파일 자체 문제. `New_1_BeforeTutorial.mp4`의 프레임 1057(35.23초) 한 장만 상체까지 보이는 넓은 구도로 들어가 있었다. 앞뒤 프레임은 다리·벤치를 가까이 잡는 같은 구도. 원본 mp4를 Unity 밖(브라우저)에서 읽어도 똑같이 나와 코드 문제가 아니다.
- 찾은 방법: 브라우저에서 영상을 한 프레임씩 넘기며 "앞뒤 프레임은 비슷한데 가운데만 다른 프레임"을 찾음. 프레임 1057 점수가 21.7로 가장 높았고, 사용자가 본 구간(1000~1100)과 일치.
- 수정: ffmpeg `freezeframes`로 1057을 1056으로 덮어씀. 영상 H.264 재인코딩(CRF 14), 소리는 복사(`-c:a copy`). 파일을 같은 경로에 덮어쓰고 `ForceUpdate`로 다시 임포트.
  ```
  ffmpeg -i 원본.mp4 -filter_complex "[0:v]split[a][b];[a][b]freezeframes=first=1057:last=1057:replace=1056[v]" -map "[v]" -map 0:a -c:v libx264 -crf 14 -preset slow -pix_fmt yuv420p -fps_mode passthrough -c:a copy -movflags +faststart 결과.mp4
  ```
- ffmpeg는 시스템에 설치하지 않고 세션 임시 폴더에 `imageio-ffmpeg` 패키지로 받아 사용.

## 결정 사항
- 코드로 특정 프레임을 가리지 않고 영상 파일을 고쳤다. 프레임 수가 그대로라 소리 싱크가 유지된다.
- `.meta`를 건드리지 않아 GUID(`5e3a4d81356070d499dc078a997e44a1`)와 `SOLoadingCutsceneData` 참조가 그대로다.

## 현재 상태 및 이슈
- 확인함: 원본과 프레임별 비교에서 1057만 18.7dB로 크게 다르고 나머지는 약 50dB 이상(평균 58dB). 전후 프레임 눈으로 확인. 임포트 후 45.33초, 1360프레임, 30fps, 1920×1080, 소리 1트랙, VP8. SO가 같은 영상을 참조.
- **게임 안 재생은 확인하지 않았다.** 소리 싱크도 청취 확인 안 함.
- 재인코딩으로 mp4 크기가 약 28.4MB → 21.5MB로 줄었다(화질 손실은 수치상 눈에 띄지 않는 수준).
- 프레임 1124·1127은 빨간 화면 사이의 검은 프레임이다. 깜빡임 연출로 보여 그대로 뒀다. 의도 여부는 사용자 확인 필요.
- 사용자가 준 `Downloads/New_Real_1_BeforeTutorial.mp4`는 스캔 도중 중단되어 **검사하지 않았고 적용하지도 않았다.**
- 이 영상은 Git이 아니라 SVN(`Assets/ThirdParty` 작업 사본, r412 기준 추적 중)으로 공유된다. 기존 파일을 고친 것이라 SVN에는 로컬 수정으로 잡히며, **SVN 커밋 전이라 팀원에게 아직 안 갔다.** 원본은 SVN 기록(r412)에 남아 있다. 서버 최신 상태는 svn CLI가 없어 확인하지 못했다.
- `RT_SkySign_*.renderTexture` 4개가 재임포트 시각(19:16)에 다시 저장되어 `git status`에 수정으로 뜬다. `git diff` 내용은 비어 있고 줄바꿈 경고만 있어 실제 변경은 없다. 건드리지 않았고 커밋할 필요 없다.
- Git에는 이 기록만 커밋했다.
