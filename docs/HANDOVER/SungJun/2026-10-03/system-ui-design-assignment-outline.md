# 시스템·UI 설계 과제 문안 검토

## 작업 요약 및 방법
- 현재 `feature/System-Manager` 브랜치의 `GameManager`, `PlayerState`, `PlayerSpawner`, 스테이지와 UI 스크립트 및 기존 설계 기록을 확인했다.
- 과제용 포트폴리오에 넣을 구현 현황, 설계 의도, 미구현 계획과 검증 시나리오를 구분해 정리했다.
- 후속 요청에 따라 UI, Stage/게임 상태, Spawn, Save, Manager, 연출/Scan을 포트폴리오 목차로 재구성했다. `Scan`, 스킬 입력 경로, AudioManager 유무도 코드에서 확인했다.

## 결정 사항
- 현재 코드에 존재하는 구조와 실행까지 연결된 기능을 구분해 설명한다.
- 씬 전환 연동, 스테이지 완료·실패 판정, 독백·안내 패널 연결은 향후 계획으로 표시한다.

## 현재 상태 및 이슈
- `GameManager`의 씬 전환 전 이벤트 연결과 씬 로드 후 스테이지 시작 호출은 미완성이다.
- `StageManager`의 진행도 및 결과 처리와 앱별 단계 로직은 골격 수준이다.
- HUD 스크립트는 존재하지만 실제 씬에서의 연결·실행 검증은 이번 세션에서 하지 않았다.
- 독백과 안내 패널 Presenter는 빈 클래스이다.
- `Scan`은 입력과 스킬 호출 경로가 있으나 실제 탐지 동작은 로그 출력뿐이다. `AudioManager`와 영구 저장 시스템은 현재 코드에서 확인되지 않는다.
- 이번 작업은 코드 수정이나 Unity 실행 없이 정적 검토만 수행했다.

## 다음 할 일
- 담당 파트가 확인되면 과제 문안을 해당 파트에 맞춰 조정한다.
- 제출 자료에는 구현 화면과 구조도, 구현/계획 표시를 넣고 Unity 실행 결과를 확인한다.
