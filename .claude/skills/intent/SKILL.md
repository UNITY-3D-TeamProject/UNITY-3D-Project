# Intent 문서 스킬

`docs/intent/README.md`에 정의된 규칙을 따라 intent 문서를 다룬다. 이 스킬은 아래 세 가지 상황에서 호출된다.

1. 새로운 작업(기능/변경)을 시작하기 전 — intent 문서를 새로 쓴다.
2. 작업 도중 intent 내용이 바뀌었을 때 — 기존 문서를 갱신한다.
3. 작업이 끝났을 때 — 문서를 `resolved`로 바꾸고 `docs/intent/clear/`로 옮긴다.

## 0. 항상 먼저 확인
- `docs/intent/INTENT_POINTER.md`를 먼저 훑어 현재 작업과 관련된 파트에 이미 열려있는 intent가 있는지 확인한다 (이슈 트래커의 인덱스처럼 취급).
- 있으면 새로 만들지 말고 그 문서를 갱신한다.

## 1. 새 intent 작성 (작업 시작 전)
1. `docs/intent/` + `docs/intent/clear/`에서 가장 큰 번호를 찾아 다음 순번(NNN, 3자리)을 정한다.
2. `docs/intent/_template.md`를 복사해 `docs/intent/intent-NNN-짧은-슬러그.md`로 만든다.
3. 아래 항목을 사용자와 함께 채운다. 확신 없는 내용은 추측하지 말고 사용자에게 질문한다.
   - **파트 (Part)**: 어느 부분/모듈 문제인지 (frontmatter `part` 필드)
   - **문제 (Problem)**: 지금 무엇이 불편하거나 안 되는지
   - **기대 결과 (Proposed outcome)**: 해결되면 무엇이 어떻게 달라지는지
   - **영향 범위 (Affected users and systems)**: 누가 쓰고 어떤 시스템/모듈이 건드려지는지
   - **제약 (Constraints)**: 예산, 기한, 지켜야 할 정책, 쓰지 말아야 할 것
   - **열린 질문 (Open questions)**: 아직 정하지 못한 것
4. frontmatter의 `status: open`, `created` 날짜를 채운다.
5. **열린 질문이 남아 있는 항목은 코딩을 시작하기 전에 사용자에게 먼저 확인한다.** 임의로 답을 정하지 않는다.
6. `docs/intent/INTENT_POINTER.md`의 "열려있는 인텐트" 목록에 파트별로 한 줄 등록한다: `- **[파트]** 문제 한 줄 요약 → [문서](./intent-NNN-slug.md)` ("현재 열려있는 인텐트 없음" 플레이스홀더가 있으면 지운다).

## 2. 진행 중 갱신
- 작업 중 범위나 제약이 바뀌면 해당 intent 문서를 바로 수정한다. 새 문서를 또 만들지 않는다.
- 열린 질문이 하나씩 해결될 때마다 해당 항목을 지우거나 답을 적어 반영한다.
- 파트나 문제 요약이 바뀌면 `INTENT_POINTER.md`의 해당 줄도 함께 고친다.

## 3. 해결 처리 (작업 마무리 시)
작업이 실질적으로 끝났다고 판단되면(요구사항 충족, 컴파일/테스트 통과 등) 다음을 수행한다.
1. 해당 intent 문서의 frontmatter를 `status: resolved`, `resolved: YYYY-MM-DD`로 바꾼다.
2. `## 해결 기록 (Resolution)` 섹션에 최종 결정과 관련 커밋/PR을 적는다.
3. 파일을 `docs/intent/`에서 `docs/intent/clear/`로 이동한다 (git mv 또는 파일 이동 후 원본 삭제).
4. `INTENT_POINTER.md`에서 해당 항목을 "열려있는 인텐트"에서 지우고 "해결됨" 목록으로 옮긴다: 링크를 `./clear/intent-NNN-slug.md`로 바꾸고 `(resolved: YYYY-MM-DD)`를 덧붙인다.
5. 열린 질문이 남아 있는데 해결로 처리하려 하면, 먼저 그 질문들이 실제로 무의미해졌는지 확인하고 아니면 남겨둔 채 `open` 상태를 유지한다.

## 4. 자동 권유 규칙
- 사용자가 명시적으로 "intent 작성해줘"라고 하지 않아도, 다음 경우에는 먼저 이 스킬 사용을 제안한다:
  - 새로운 기능/시스템 구현을 시작하려는 요청을 받았는데 관련 intent 문서가 없을 때
  - 진행 중이던 intent 문서의 요구사항이 이번 대화에서 충족된 것으로 보일 때 (해결 처리 제안)
- 제안은 짧게 한 문장으로 하고, 사용자가 원치 않으면 넘어간다. 강제로 문서를 만들거나 이동시키지 않는다.
- 세션 종료(Stop) 시점에는 `.claude/settings.json`에 등록된 Stop 훅이 `docs/intent/`에 남아있는 open 문서 개수를 자동으로 감지해 리마인드 메시지를 띄운다. AI가 매번 직접 확인할 필요는 없지만, 리마인드가 뜨면 이번 세션에서 다룬 intent가 있는지 확인하고 해결 처리 여부를 사용자에게 물어본다.
